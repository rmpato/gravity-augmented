What you walk out with

Three things, built commit by commit

GCP, essentials → solid intermediate

Projects, IAM, Cloud Run, Cloud SQL, Memorystore, Pub/Sub, Cloud Load Balancing, Cloud CDN, Cloud Monitoring, Artifact Registry, Terraform, and the judgement to pick between them.

System design, at least intermediate

Caching, sharding, replication, consistency, queues and delivery semantics, backpressure, service boundaries, deploys, observability, and how to defend a design out loud.

A real system you built yourself

Scouter starts as one Go binary with an in-memory map. It ends as a set of services with a database, a cache, a CDN, a message bus, traffic-split deploys and SLOs, all in your own repo.

How a capsule works

The same loop, every time

About 15 minutes of reading, 30 of hands-on and 5 of writing it down. Nothing requires you to hold the previous week in your head.

  1. Read the conceptThe real production problem first, then the actual teaching.
  2. Do the labNumbered steps in your repo. Type the code; don't paste it.
  3. Break it on purposeKill the container, fire 10× traffic, unplug the cache. That failure is the lesson.
  4. Pass the checkpointCommands with expected output. Passing is what "done" means.
  5. Log itCommit in gravity-chamber, then scouter done NN.

Start here

Clone, check, read

Python 3 standard library and a POSIX shell. No pip install, no npm install, no build step.

git clone https://github.com/rmpato/gravity-augmented
cd gravity-augmented

./bin/doctor          # what's missing on your machine
./bin/serve           # the reader on localhost:8420
./bin/scouter next    # what to do now

Arc recap

Finishing a capsule is not learning it

Without retrieval you lose most of it within a week, and rereading barely helps. scouter review asks you to recall each capsule again at 3, 7 and 21 days.

When you close out a saga, the recap gives every capsule one page: the idea in plain words, a diagram of the mechanism, the traps, and a drill to answer from memory.

Cost

This will not surprise you with a bill

Every lab runs locally first: Docker, Postgres, Redis, and the Pub/Sub and Firestore emulators. Where real GCP teaches something local tooling can't, it's a clearly fenced, free-tier, optional section with teardown at the end, and you set up a budget alert before your first gcloud command.

First release. The code is verified: every Go snippet compiles, every embedded calculation was executed, and the labs were run against real containers rather than just written. What hasn't been tested is the teaching. If a step assumes something it never told you, that's a bug, and it's the most useful thing you can send back.
